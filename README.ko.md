# GITHUB INSIGHT

[대시보드 열기](https://nowwcastle-sudo.github.io/github-trending-daily/) · [English](README.en.md)

GitHub Trending 저장소의 용도, 사용법, 활동과 스타 이력을 확인하는 정적 대시보드입니다. 저장소 README를 근거로 생성한 요약을 함께 보여줍니다. 조회에는 계정이 필요하지 않습니다. Google 로그인은 즐겨찾기를 동기화할 때 선택합니다.

## 저장소 탐색

일간·주간·월간·전체 보기를 선택합니다. 검색어와 프로그래밍 언어, 분야, 형태, 기술, 즐겨찾기, AI 제외, 신규 저장소 조건을 조합합니다. 같은 그룹 안은 OR, 서로 다른 그룹 사이는 AND로 적용합니다.

| 보기 | 포함 기준과 Trending 정렬 | 기간 지표 |
| --- | --- | --- |
| 일간·주간·월간 | 해당 기간의 유효한 멤버십이 있는 저장소. 그 기간의 순위 사용 | 선택 기간 증가량·HOT·스파크라인 |
| 전체 | 세 기간 목록의 합집합. 수집 원본 순서 유지 | 총 스타와 별도로 표시한 일간 증가량. 전체 기간 증가량·HOT·스파크라인은 없음 |

증가량이 없으면 없는 값으로 유지합니다. 출처가 실제로 0을 보고하면 0을 유지합니다. HOT은 선택 기간의 보고 증가량이 1,000 이상이라는 뜻입니다. 전체 보기는 GitHub가 발표한 별도 순위가 아닙니다. 기간 증가량, 총 스타, 최근 push, 최근 release로도 정렬할 수 있습니다. 열린 이슈 수에는 GitHub API가 함께 집계하는 PR이 포함됩니다.

## 요약과 상류 README

데스크톱에서는 카드에 포인터를 올리거나 초점을 둡니다. 모바일에서는 카드를 탭합니다. 헤더에서 영어·한국어·중국어 간체·스페인어·일본어 중 UI와 요약 언어를 선택합니다.

| 필드 | 내용 |
| --- | --- |
| `goal` | 저장소가 하는 일 |
| `usage` | 출처에 근거한 설치·사용 방법 |
| `pros` | 출처로 뒷받침한 장점 |
| `cons` | 제약. 추론에는 추론임을 표시 |
| `fit` | 맞는 사용자와 사용 상황 |

**View README**는 정본과 상류 저장소에 실제 존재하는 언어판만 엽니다. 경로, 기본 브랜치 head, blob SHA, 내용 SHA-256으로 출처를 연결합니다. README 전체 번역본을 생성하거나 저장하지 않습니다.

요약은 AI가 생성하고 자동 검사합니다. 사람이 검토한 추천을 뜻하지 않습니다. 설치 전에는 상류 문서와 보안 요구사항을 확인해야 합니다.

## 요약 게시 기준

저장소·README 수집과 출처 검증을 마친 뒤 생성합니다. 다섯 언어를 하나의 원자적 묶음으로 처리합니다. 필드는 서로 다른 역할을 지키며 설치·실행 방법은 `usage`에 둡니다. 영어 묶음은 100~280단어입니다. 다른 언어의 표현·문장 수·정보 순서는 영어와 같을 필요가 없습니다.

README에 실제 있는 핵심 명령을 1~2개만 인용합니다. 명령 등 원문 유지 대상은 언어별 대응 필드에서 출처와 일치해야 합니다. 일반적인 “README를 참고하라” 식의 요약은 허용하지 않습니다. 첫 생성 후 교정은 최대 세 번입니다.

현재 의미 품질 판정 모델은 영어를 검사합니다. 나머지 언어에는 스키마·문구·언어 간 불변값 검사도 적용합니다. 다섯 언어 전체를 의미 검토한다는 뜻은 아닙니다.

| 상태 | 의미 |
| --- | --- |
| `verified` | 이번 실행에서 생성하고 검사한 요약 |
| `retained` | 현재 재사용 조건을 통과한 기존 요약 |
| `held` | 수집 지표는 유지하고 요약 대신 지역화된 검증 안내 표시 |

보류 저장소는 이후 갱신에서 다시 검토합니다. 분류 실패도 해당 요약을 보류합니다. 저장소 하나가 보류됐다는 이유만으로 전체 갱신을 실패시키지는 않습니다. **전체의 50%를 초과해 보류되거나 검증·재사용 가능한 요약이 하나도 없으면 후보 전체를 거절합니다.** 수집·출처·산출물 검사 실패도 게시를 중단할 수 있습니다.

## 스타와 이력

| 지표 | 출처와 의미 |
| --- | --- |
| 총 스타 | GitHub 저장소 API 직접 관측 |
| 일간·주간·월간 증가량 | GitHub Trending의 기간 집계 |
| 그래프 실선 | 이 사이트가 기록한 직접 관측 |
| 빈 마커가 있는 점선 | 직접 관측이 없는 구간을 Trending 증가량으로 역산한 근사 앵커 |

게시 중인 저장소는 매시 UTC 13분·43분에 관측하도록 예약합니다. 과거 게시 저장소도 아카이브 관측 대상입니다. UTC 하루 최대 한 번, 7일 증가량 기준 500개 한도 안에서 관측합니다. 실제 실행은 지연되거나 API 잔여 한도와 다른 실행 때문에 생략·대기할 수 있습니다. 성공한 관측 두 번이면 첫 선을 그릴 수 있습니다. 하루치 곡선이 쌓이는 고정 시간을 보장하지 않습니다.

GH Archive·OSS Insight의 이벤트 기반 과거 추정치는 상류의 심각한 품질 저하 공지에 따라 2026-09-02에 중단했습니다.

멤버십 이력은 기준선에 이미 있던 저장소, 기준선 이후 처음 등장한 저장소, 목록에서 빠졌다가 재진입한 저장소를 구분합니다. “지난 방문 이후 새로 올라옴”은 이 브라우저의 이전 방문과 비교하는 별도 신호입니다.

## 패널·즐겨찾기·내보내기

| 레일 그룹 | 기능 |
| --- | --- |
| Login·로그인 | Google 로그인, 즐겨찾기 동기화 |
| Explore·탐색 | 필터, 정렬, 저장한 프리셋 |
| History·이력 | 숨긴 저장소 복구, 멤버십 변화 |
| Export·내보내기 | 현재 보기 CSV·JSON, 공유 탐색 URL |

데스크톱 hover는 비모달 사이드바를 엽니다. 클릭·키보드 실행은 초점이 패널 안에 머무는 모달을 엽니다. 모바일은 가장자리 스와이프를 지원합니다. 라이트·다크 테마, 간단히 보기, 동작 줄이기, 투명도 줄이기도 지원합니다.

로그아웃 상태에서도 즐겨찾기를 로컬에 저장합니다. **관심 없음**은 이 브라우저에서 숨기며 되돌리기·복구를 지원합니다. 숨겨도 즐겨찾기는 삭제하지 않습니다. 필터 프리셋은 브라우저에 이름을 붙여 최대 20개 저장합니다.

| 단축키 | 동작 |
| --- | --- |
| `/`, `?`, `Escape` | 검색, 단축키 도움말, 닫기 |
| `a`, `e`, `h`, `x` | 로그인, 탐색, 이력, 내보내기 |
| `Delete` | 현재 선택한 저장소 숨기기 |

도움말에서 한 글자 단축키를 끌 수 있습니다. 공개 탐색 URL에는 개인 즐겨찾기·숨김 목록을 넣지 않습니다. CSV·JSON은 현재 보기의 공개 필드만 담습니다. CSV에는 UTF-8 BOM을 넣고 특수문자를 인용 처리합니다. 수식으로 실행될 수 있는 값 앞에는 작은따옴표를 붙입니다.

Atom으로 [현재 저장소](https://nowwcastle-sudo.github.io/github-trending-daily/feed.xml)와 [신규·재진입 저장소](https://nowwcastle-sudo.github.io/github-trending-daily/changes.xml)를 구독할 수 있습니다.

## 전체 갱신과 게시

전체 갱신 예약 시각은 **한국 00:07·06:07·12:07·18:07**입니다. 각각 **UTC 15:07·21:07·03:07·09:07**입니다. GitHub Actions 예약은 정확한 실행 시각을 보장하지 않습니다. 요약 생성에는 전용 Windows 러너가 온라인이어야 합니다.

파이프라인은 저장소·README 사실 동결, 이벤트 수집, 요약 생성·재사용, 스냅샷 기록, 피드·이력 파생, 후보 전체 검증, Pages 산출물 생성을 수행합니다. 이후 커밋·배포하고 운영 사이트를 검사합니다. 배포된 후보의 검사에 실패하면 검증된 이전 산출물로 복구를 시도합니다. 복구에 성공해도 실패한 갱신을 성공으로 바꾸지는 않습니다.

게시 전 후보가 실패하면 기존 페이지를 교체하지 않습니다. 별점 관측 실행은 관측 오버레이를 갱신합니다. 전체 목록 갱신을 대신하거나 확정되지 않은 코드 변경을 배포하지 않습니다.

러너 래퍼는 자동 업데이트 뒤 다시 시작하도록 공식 `run.cmd`를 호출해야 합니다. [러너 복구 안내](docs/enrichment-runner.md)에 절차를 정리했습니다. 대기 시간 감시, 조건에 맞는 인프라 실패 재시도, 러너 오프라인 이슈도 진단에 사용합니다.

## 로컬 실행과 검증

CI와 같은 Node.js 24, Python 3.13을 사용합니다. PowerShell에서 저장소 루트로 이동한 뒤 실행합니다.

```powershell
npm ci
npm test
```

`npm test`는 Node 테스트와 Python unittest를 모두 실행합니다. 운영체제 전용 테스트와 Firestore 에뮬레이터가 필요한 테스트가 있으므로 건수와 생략 사유를 함께 확인합니다.

Firestore 규칙 검사는 Firebase Emulator Suite가 지원하는 Java 런타임을 설치한 뒤 실행합니다.

```powershell
npm run test:rules
```

`npm run test:all`은 두 검증을 함께 실행합니다. 정적 UI는 다음 명령으로 확인합니다.

```powershell
python -m http.server 8000
```

[localhost:8000](http://localhost:8000/)을 엽니다. Google 인증에는 프로젝트 Firebase 설정과 허용된 호스트가 필요합니다. 로컬 파일 제공만으로 계정 동기화를 검증할 수는 없습니다.

수집·요약 생성 자격 증명은 GitHub Actions와 러너 사용자 저장소에서 관리합니다. 프런트엔드 파일에 넣지 않습니다. 브라우저는 공개 데이터·README 출처를 읽으며 선택적 계정 기능은 Firebase·Google에 접속합니다.
