# GitHub Trending Daily — 기능제안검토서 (최종본)

**작성**: ox-alpha · **검토 방식**: understand-anything 코드베이스 분석(노드 99·엣지 123) + 1차 검토안 + REDTEAM 3관점(보안 공격자 / 제품 YAGNI / 장기 운영) 교차 검증
**대상**: ChatGPT 감사 보고서(commit `1f7caa8`, main 기준)의 전체 제안
**원칙**: 이 저장소는 **혼자 쓰는 도구이면서 공개 서비스**라는 이중성을 가짐. 모든 판정은 "보안 경계는 엔터프라이즈급, 기능은 개인 도구급"으로 나눴다.

## 1. 한 줄 결론

ChatGPT 보고서는 정확하지만 **"무엇을 고치고 무엇을 버릴지"의 우선순위가 비즈니스 컨설팅 톤으로 되어 있어**, 혼자 운영하는 실제 상황에 적용하면 과부하가 온다. 본 검토서는 3개 REDTEAM의 반박을 반영해 다음과 같이 재배열한다:

> **① 보안·CI 경계 정리 → ② 파이프라인 실패 알림(신규 발견!) → ③ 데이터/앱 분리(최소 단위, 조건부) → ④ SQLite 저비용 배지 기능만. 나머지는 전부 유예.**

특히 REDTEAM #3이 발견한 것 중 가장 중요한 것: **이 사이트의 핵심 차별점인 한국어 요약이 scripts/ 어디에도 자동화 코드가 없다는 사실**이다. 매일 사람이(에이전트 세션으로) 수작업으로 돌리는 중이며, 이것이 문서화 없이는 운영자 2주만 손을 놓아도 사이트 품질이 붕괴된다.

## 2. ChatGPT 제안별 최종 판정

### ✅ 즉시 실행 (모든 REDTEAM 합의)

| 제안 | 판정 | REDTEAM 관점에서 추가된 것 |
|---|---|---|
| SRI + exact 버전 고정 + CSP | **실행** | [R1-F1] DOMPurify 우회 시 종착점이 "세션 탈취"가 아니라 **Firestore 영구 쓰기**(globalThis.favoriteController 노출). CSP를 단순 보조가 아닌 쓰기 차단선으로 설계 |
| Actions `persist-credentials:false` + SHA pinning | **실행** | 동의 |
| test/publish job 분리 | **실행** | — |
| ci.yml 신설 + `test:all` (rules 테스트 포함) | **실행** | [R3] rules 테스트는 좋은데 게이트 미연결 — 지적 정확 |

| workflow schedule 중복 제거 | **실행** | [R3] concurrency group race 이미 잠재 |

### ⚠️ 조건부 실행

| 제안 | 판정 |
|---|---|
| REPOS → data/trending.json 분리 | **실행하되 조건부**: [R2] ES modules 전환과 **완전히 분리**할 것. 선행조건 = ci.yml이 main에서 N일간 green. 롤백 사고(page_template 사건) 이력이 있는 프로젝트에서 대규모 리팩토링을 CI 안전망 없이 하면 재발 위험 |

| README Viewer 강화 (timeout/size limit/img 차단) | **실행** — 저비용 고효과. `referrerpolicy=no-referrer` 포함 |

## 3. REDTEAM에서 새로 발견된 것 (두 보고서 모두 놓친 것)

### 🔴 R1-F1 [High] XSS 종착점 = Firestore 영구 오염
CSP/SRI 논의가 "스크립트 로드 차단"에 머물렀는데, 실제 위험은 XSS 성공 시 `globalThis.favoriteController.toggle()` 호출로 피해자 클라우드 문서에 영구 기록되는 것. → CSP 설계 시 **쓰기 API 호출 차단** 관점 추가 필요.

### 🟠 R1-F2 [Medium] `lang`·`color` 이스케이프 누락 (index.html:354, :427)
`langSel.insertAdjacentHTML`에 GitHub API 문자열 원문 삽입. `inlineJson` escaping은 잘 되어 있지만 이 렌더 경로가 유일한 누수. **확정된 신규 결함.**

### 🟠 R1-F3 [Medium] localStorage → 클라우드 import 오염 경로
최초 로그인 시 `gh-favs-guest`가 일회성 union import되는데, 공유 PC/악성 확장이 이 값을 조작하면 피해자 로그인 순간 오염이 **영구 반영**됨(재동기화 없음).

### 🟠 R1-F4 [Medium] Firebase 부트스트랩 실패 = 보안 fail-open
`bootstrap().catch(keepGuestMode)`가 projectId 검증 실패까지 흡수 → App Check 없이 조용히 게스트 모드. resilience가 아니라 **보안 기능의 무단 비활성화 경로**.

### 🔥 R3-4 [Critical — 운영] 한국어 요약이 문서화 안 된 수작업
scripts/ 전체에 LLM/API 코드 0개. 요약 품질이 갈리는 이유(고도화 vs "저장소 문서 참조." 폴백)의 원인. **운영자의 매일의 시간으로 지불되는 숨은 비용.**
→ **제안**: 요약 생성을 GitHub Action으로 자동화하거나, 최소한 절차를 RUNBOOK에 문서화.

### 🔥 R3-1~3 [High] 파이프라인 실패 시 조용한 죽음
실패 알림·issue 생성·복구 전략 전무. Trending 마크업 변경 시 **오래된 스냅샷을 무기한 서빙**하고 아무도 모름.
→ **제안**: workflow failure 시 issue 자동 생성 + webhook 알림 (반나절 작업).

### 🔥 R3-2 SQLite git 커밋 구조
61KB 시작, append-only로 영구 blob 팽창. binary라 merge conflict 수동 해결 불가, 백업 전략 전무.
→ **제안**: 주기적 dump backup job 추가.

### 🔥 R3-5~7 Bus factor
Firebase 소유 계정 정보, RUNBOOK, 배포 구조 설명 전무. `.ua/tmp/`의 검토 문서들(이 문서 포함)도 저장소 산출물이 아님.

## 5. ChatGPT 보고서 평가

**정확도: 높음.** 보안 감사(SEC-01~06), 아키텍처 진단(§12~17) 모두 코드 실측으로 재검증 결과 오류 없음. 특히 §8(파이프라인이 강점)과 §21(방어적 구현 칭찬)은 편향 없이 사실만 기술한 좋은 균형 감각.

**한계 3가지**:
1. **운영 관점 부재** — 6개월 후 시나리오가 없음. REDTEAM #3이 채운 영역 (알림 부재, SQLite 백업, bus factor).
2. **단일 사용자 현실 무시** — 기능 ★★★★★ 평가가 "구현 가능성" 기준이지 "사용 빈도" 기준이 아님.
3. **누락**: ui-motion.js(모바일 UX 핵심) 리뷰 완전 누락, `lang`/`color` esc() 누락(F2), localStorage import 오염 경로(F3), Firebase fail-open(F4).

**좋았던 것**: React/Next 전환을 권하지 않은 점, §8/§9에서 잘한 부분을 명확히 칭찬한 점 — 이 두 가지가 있어서 감사 보고서가 방어적 태도가 아니라 개선 파트너십으로 읽힘.
