# Google Favorites Sync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Google sign-in and secure same-account favorites synchronization while preserving a fully working browser-local guest mode.

**Architecture:** Firebase Authentication owns Google OAuth and yields a UID; Cloud Firestore stores one allowlisted document per UID. DOM-free storage and synchronization logic is tested with injected adapters, while a thin pinned Firebase browser module connects that logic to the official SDK. Firestore Security Rules and Emulator tests enforce owner-only access independently of the UI.

**Tech Stack:** Vanilla JavaScript, Firebase Web SDK 12.17.1 browser modules, Firebase Authentication, Cloud Firestore, Firebase CLI 15.28.1, `@firebase/rules-unit-testing` 5.0.2, Node.js 24 `node:test`

**Spec:** `docs/superpowers/specs/2026-08-22-star-history-google-auth-design.md`

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{uid} {
      function isOwner() {
        return request.auth != null && request.auth.uid == uid;
      }
      function validDocument() {
        return request.resource.data.keys().hasOnly(['favorites', 'updatedAt'])
          && request.resource.data.keys().hasAll(['favorites', 'updatedAt'])
          && request.resource.data.favorites is list
          && request.resource.data.favorites.size() <= 500
          && request.resource.data.updatedAt == request.time;
      }
      allow get: if isOwner();
      allow list: if false;
      allow create, update: if isOwner() && validDocument();
      allow delete: if isOwner();
    }
  }
}

- [ ] **Step 3: Implement the smallest explicit state machine**

Use a monotonically increasing generation number in `setUser()` and increment it before unsubscribing. Before each asynchronous result changes state, require both the captured generation and UID to still match. Later logins treat cloud as canonical; account cache is fallback display only after read failure.

```js
async function toggle(slug) {
  if (!Favorites.isValidSlug(slug)) throw new Error("invalid favorite slug");
  if (busy) throw new Error("favorites are still synchronizing");
  const before = [...current];
  const adding = !before.includes(slug);
  if (adding && before.length >= 500) throw new Error("favorites cannot exceed 500");
  setCurrent(adding ? [...before, slug] : before.filter(value => value !== slug));
  const optimisticRevision = revision;
  if (!uid) {
    Favorites.writeFavs(storage, "gh-favs-guest", current);
    return adding;
  }
  try {
    await (adding ? cloud.add(uid, slug) : cloud.remove(uid, slug));
    Favorites.writeFavs(storage, `gh-favs-cache:${uid}`, current);
    return adding;
  } catch (error) {
    if (revision === optimisticRevision) setCurrent(before);
    onMessage("즐겨찾기를 동기화하지 못해 이전 상태로 되돌렸어요.", "error");
    throw error;
  }
}
```

`setCurrent()` increments `revision` on every optimistic change and every accepted snapshot. The watch callback normalizes values, updates the account cache, and calls `onState`; therefore a newer snapshot prevents an older rejected write from rolling it back. `dispose()` invalidates the generation and invokes the active unsubscribe exactly once.
